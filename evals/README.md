# product-planning の eval

`set-product-north-star` と `set-product-strategy` はどちらも `grill` を `playbook:` で呼び、利用者との対話でトレードオフを確かめてから資料を書く。`claude -p`（対話なし・tool無し）の1往復では対話と保存を観測できないので、自動実行は行わず手動evalを記録する。`scenarios.json` は agent が読む会話fixture（`scripts/evaluate-skills.py` の入力形式）であり、対話を要する入口なので 2026-09-16 の実行対象から外した。

## 手動evalの手順（代表1本: `set-product-north-star`）

| 項目 | 内容 |
|---|---|
| 実施者 | 利用者役1名（Claude Code または Codex の実セッションで `set-product-north-star` を呼ぶ） |
| 入力 | 依頼文「中小の飲食店向け予約管理の北極星を対話で作って。受益者は店主、いまは電話予約の取りこぼしが困りごと」。追加資料は渡さない。保存先は既存の書き込める一時directoryの絶対pathと `.md` 名 |
| 利用者の発言 | grillの問いに対し、受益者は「店主」、非目標は「配達・決済は扱わない」と答え、見直し条件は推奨のまま受け入れる。最後に一覧へ合意する |
| 観測1 | 問いが一問ずつ推奨付きで出て、6問以下で、超過分は未決として提示される（対話規律の本文はこの入口に無く grill に委ねている） |
| 観測2 | 戦略・行動計画（施策、順序、資源配分）が北極星資料に混ざらず、混ぜようとする発言があれば `set-product-strategy` の責務として分けられる |
| 観測3 | 合意後にだけ `verify.py` が標準入力の本文で通り、その後に write-doc で保存される。保存前に完了と述べない |
| 観測4 | 資料の `## 未決` に、問わなかった論点が推奨付きで載る |
| 記録 | 会話の全文、保存された資料、観測1〜4の根拠箇所の引用を `evals/runs/<YYYY-MM-DD>/set-product-north-star-manual.md` に保存する。観測できなかった項目は「未観測」と書き、合否にしない |
